# 验收标准设计

## 1. 基本要求

验收标准必须说明“检查什么、怎样算通过、用什么证据证明”。

| ID | 检查对象 | 通过条件 | 验证方法 | 证据 |
|---|---|---|---|---|
| AC-01 | 输入文件 | 所有文件均有处理状态 | 与目录清单比对 | 文件清单 |
| AC-02 | 文档 | 必填章节完整 | 模板检查 | 文档路径 |
| AC-03 | 数据 | 关键值有来源定位 | 抽查参数记录 | 页码/表格 |
| AC-04 | 软件 | 指定测试通过 | 执行测试 | 测试日志 |

## 2. 可验证标准类型

- 存在性：文件、字段、报告是否存在。
- 完整性：是否覆盖全部指定对象。
- 正确性：是否满足公式、规范或测试预期。
- 追溯性：能否定位来源、版本、页码、提交或记录。
- 一致性：多个文件、接口、字段是否一致。
- 权限合规：是否发生未经授权的操作。
- 人工评审：需要专业人员判断的内容。

## 3. 避免的表述

不建议只写“内容完善、质量较高、全面优化、没有问题、充分考虑”。

应改写为具体检查项，例如：
- 列出所有已识别问题及证据；
- 指定测试集全部执行并报告结果；
- 每个关键参数均有来源页码；
- 未解决问题明确列入遗留清单。

## 4. 验收状态

- **PASS**：所有关键条件满足。
- **PARTIAL**：部分满足，差距和影响明确。
- **FAIL**：关键条件未满足。
- **BLOCKED**：因输入、权限或外部依赖无法继续。
- **NOT RUN**：检查尚未执行。

不要把“没有测试”写成 PASS。
