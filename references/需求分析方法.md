# 需求分析方法

## 1. 目标

把自然语言需求转换为结构化需求，但不把分析过程变成冗长问卷。

## 2. 需求要素

| 要素 | 核心问题 | 常见缺口 |
|---|---|---|
| 背景 | 为什么现在要做？ | 现状和痛点不明 |
| 目标 | 什么结果才算成功？ | 目标只有“优化/完善” |
| 用户/使用者 | 谁使用结果？ | 使用场景不明 |
| 输入 | 从哪里取得资料？ | 路径、权限、版本不明 |
| 输出 | 交付什么？ | 格式、位置、粒度不明 |
| 范围 | 本次处理哪些对象？ | 范围可能无限扩张 |
| 非目标 | 明确不做什么？ | AI 容易自行扩展 |
| 约束 | 有哪些技术、平台、时间限制？ | 隐含限制未记录 |
| 质量 | 正确性如何证明？ | 缺少证据 |
| 权限 | 哪些操作已获授权？ | 修改/发布权限不明 |
| 风险 | 什么情况会阻断？ | 缺少异常处理 |

## 3. 信息状态标记

- **已明确**：用户明确提供，或已从当前可访问资料验证。
- **可默认**：影响较小且可逆；必须在任务书中说明默认值。
- **待确认**：会显著影响结果、范围、风险或权限。
- **未知**：当前无法获得，不得推断为事实。

## 4. 澄清优先级

1. 目标方向；
2. 输入可访问性；
3. 工作范围与非目标；
4. 输出形式和位置；
5. 权限边界；
6. 验收方式；
7. 其他偏好。

一次优先问一个问题。只有当问题之间紧密相关且合并回答更方便时，才一次询问多个字段。

## 5. 需求摘要格式

```markdown
### 需求理解
- 目标：
- 背景：
- 已有输入：
- 预期输出：
- 已明确边界：
- 当前未知：
- 当前成熟度：M0/M1/M2/M3/M4
- 下一步最关键问题：
```

## 6. 何时停止澄清

当剩余未知项不影响主要方向、可以作为明确假设、可在执行阶段设置检查点，或可列为待确认事项且不会导致越权，即可进入方案设计，不必追求信息绝对完整。
