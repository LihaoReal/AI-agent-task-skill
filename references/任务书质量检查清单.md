# 任务书质量检查清单

生成初稿后逐项检查。简单任务可裁剪，但权限、范围和验收不可忽略。

## A. 目标与需求
- [ ] 任务目标具体且可理解。
- [ ] 背景和现状足以解释任务动机（如适用）。
- [ ] 已区分用户事实、AI 假设和建议。
- [ ] 未把建议误写成用户已确认决定。

## B. 输入与输出
- [ ] 输入资料、路径、链接或获取方式明确。
- [ ] 已说明访问失败或资料缺失时的处理方式。
- [ ] 交付物名称、格式、位置和粒度明确。
- [ ] 任务书可脱离聊天上下文独立阅读。

## C. 范围与执行
- [ ] 本次工作范围明确。
- [ ] 非目标或禁止扩展的范围明确。
- [ ] 执行步骤有合理顺序。
- [ ] 复杂任务设置阶段交付或检查点。
- [ ] 依赖关系和执行角色明确（如适用）。

## D. 质量与验收
- [ ] 质量要求不是纯主观形容词。
- [ ] 关键验收项可验证。
- [ ] 每个关键验收项有通过条件或证据。
- [ ] 人工评审和自动检查已区分。
- [ ] 未执行的测试不会被宣称通过。

## E. 权限与风险
- [ ] 允许、禁止、需确认的操作已区分。
- [ ] 删除、覆盖、重构、发布、推送等高影响操作有授权边界。
- [ ] 关键资料缺失、冲突或无法访问时有暂停规则。
- [ ] 未知信息没有被编造成事实。
- [ ] 有必要的回退或停止条件。

## F. 文档质量
- [ ] 术语和字段前后一致。
- [ ] 没有相互冲突的要求。
- [ ] 没有无意义的重复章节。
- [ ] 任务复杂度与文档长度匹配。
- [ ] 任务书有版本/状态或确认记录（如适用）。

## 审查结论
- 阻断问题：
- 重要问题：
- 优化建议：
- 当前成熟度：M0/M1/M2/M3/M4
- 建议：继续澄清 / 生成初稿 / 用户审查 / 可请求定稿

**注意：质量检查通过不代表用户已经批准任务书，也不代表执行操作已获授权。**
